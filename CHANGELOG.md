## [Unreleased]

### Добавлено

- Рабочее пространство `/workspace`: три связанные области (исходник, задача,
  сценарий), регулируемые разделители, пять подготовленных ситуаций, связь
  назначения и изменения по устойчивому ID смены. Отдельный маршрут и чанк,
  эстетика лендинга сохранена. Подробности: `docs/WORKSPACE_DEMO.md`.
- Локальный backend `backend/`: FastAPI, PostgreSQL 16, миграции Alembic,
  CSV/XLSX-импорт с предпросмотром и подтверждением, неизменяемые версии
  источника и условий, хранение оригиналов с hash, история и экспорт.
  Изолированный кластер поднимается в игнорируемом каталоге `.wuji-data/`.
  Подробности: `docs/DATA_STAGE.md`, `backend/README.md`.
- Расчёт на OR-Tools CP-SAT в отдельном worker-процессе с очередью в PostgreSQL:
  независимый серверный валидатор, метрики и Evidence, отмена, повтор,
  обнаружение потерянных запусков, частичное закрепление с новым расчётом.
  Подробности: `docs/CALCULATION_STAGE.md`.
- Серверный адаптер OpenAI: текст становится отдельным черновиком условий со
  строгой схемой и дословными цитатами, которые сервер сопоставляет с
  исходником. Провайдер получает только текст пользователя, часовой пояс и даты
  недели — ни списка сотрудников, ни ставок, ни доступности. Подробности:
  `docs/INTENT_STAGE.md`.
- Утверждение проверенного варианта и выдача CSV/XLSX с квитанцией, контрольной
  суммой файла и повторным чтением экспорта. Подробности: `docs/APPROVAL_STAGE.md`.
- Проверки: `npm test` (39), `npm run test:api` (132), `npm run api:types:check`,
  общая команда `npm run check` и workflow `.github/workflows/verify.yml`
  (удалённый запуск ещё не выполнялся).
- Причины доказанной невозможности: вместо общего «минимальный набор причин не
  определялся» расчёт называет конфликтующие условия — смены, сотрудников и само
  условие. Покрыты закрепление на сотруднике без роли, на недоступном, сверх лимита
  часов, смена, которую некому взять, пересечение двух закреплений, а также любые
  другие сочетания: список форм не используется. Модуль `backend/app/diagnosis.py`:
  отдельная модель с предположениями CP-SAT только предлагает конфликт, основная
  модель их не получает. Каждое утверждение проверяется обычным поиском на основной
  модели со снятым условием и независимым валидатором; отчёт говорит и о том, какое
  условие снимать бесполезно. Новое поле `SolveIssue.conditions`, код `conflict`;
  коды `pinned_absence`, `fixed_absence`, `fixed_pin_conflict` сохранены. Диагностика
  укладывается в `max_seconds`, при нехватке времени остаётся прежний общий ответ.
  Варианты, `outcome`, статус запуска и попытки поиска не меняются. Версия движка
  остаётся `schedule-cpsat/3`: решение о её повышении за владельцем. Подробности:
  `docs/CALCULATION_STAGE.md`.
- Планы продукта и реализации: `docs/PRODUCT_PLAN.md`, `docs/IMPLEMENTATION_PLAN.md`.
- `vercel.json` — конфигурация деплоя на Vercel (framework `vite`, сборка в `dist`,
  rewrite всех путей на `index.html`).
- Раздел «Деплой на Vercel» в `README.md`.
- Продакшен развёрнут: https://wuji-project.vercel.app (автодеплой из `main`).

### Изменено

- `base` в `vite.config.ts`: `'./'` → `'/'`. Пути к ассетам в сборке стали
  абсолютными, вложенные маршруты больше не ломают загрузку JS, CSS и картинок.
- Навигация лендинга: добавлен вход `WORKSPACE ↗`, логотип вынесен в общий
  компонент `BrandMark` с прежней разметкой.
- `Home.tsx`: callback GSAP снимается при уходе с лендинга, чтобы плавная
  прокрутка не оставляла обработчики.

### Исправлено

- `backend/app/solver.py`: невозможность выдавалась за нехватку данных. Если
  решения не было по причине, не связанной с неизвестной доступностью
  (закрепление на отсутствующем, на сотруднике без роли, на недоступном или сверх
  лимита часов, смена, которую некому взять), но где-то оставалось неизвестное
  значение, расчёт завершался `needs_clarification` с «уточните неизвестную
  доступность» — человека отправляли чинить не то. Теперь в этом случае
  выполняется ещё один поиск, где вся неизвестная доступность считается
  подтверждённой. Если решения нет и так, ответ — доказанная невозможность; если
  решение появляется или лимит исчерпан, вопрос остаётся. Этот поиск ничего не
  публикует и виден только в журнале расчёта. Отдельно названы коды
  `fixed_absence` (закрепление условий на отсутствующем) и `fixed_pin_conflict`
  (закрепления условий и исходника называют разных людей). Если решение есть,
  назначения и метрики те же. Для описанных условий меняются `outcome` (на
  `infeasible`) и статус запуска (на `completed`), поэтому версия движка поднята
  до `schedule-cpsat/3`. Сохранённые запуски и их экспорт остаются со своей версией.
- `src/App.tsx`: несуществующий адрес рендерил пустой чёрный экран с
  `No routes matched location` в консоли — rewrite Vercel отдаёт `index.html`
  на любой путь, а маршрута `*` в роутере не было. Добавлена страница 404
  в существующем стиле со ссылкой на главную.
- `backend/app/main.py`: `team_name` с управляющим символом давал
  необработанный 500 — `\u0000` отвергается JSONB раньше, чем валидатор
  импорта успевает сообщить о проблеме. Теперь это 422 с кодом `team_name`,
  как и проверка имени файла рядом.
- `backend/app/local_db.py`: локальный кластер не стартовал там, где у процесса
  пустой `LANG` и выставлены переменные CoreFoundation (запуск из macOS-приложения) —
  postmaster прерывался с `became multithreaded during startup`. `initdb` и
  `pg_ctl start` теперь получают `LC_ALL=C`, что согласовано с `--no-locale`.
- `backend/app/main.py`: ответ 422 называл ошибку, но не поля — `issues` всегда
  приходил пустым. Теперь сообщение перечисляет пути полей; значения, которые
  Pydantic кладёт в `msg` и `input`, по-прежнему не раскрываются.
