# WUJI Local Workspace API

Локальный сервер проектов, импорта, неизменяемых версий, подтверждаемых текстовых черновиков, расчётов, ручной проверки, утверждений и выдачи результата. FastAPI, PostgreSQL 16+, SQLAlchemy, Alembic, OR-Tools CP-SAT, OpenAI SDK. Адаптер провайдера реализован; успешный живой ответ ещё не проверен.

## Запуск

Нужны Python 3.12, `uv` и PostgreSQL 16+ с `initdb`/`pg_ctl` в PATH. Из корня репозитория:

```bash
npm install
npm run api
```

В другом терминале:

```bash
npm run dev
```

Открыть `/workspace`, затем `[+ ИМПОРТ]` или `[ПРОЕКТЫ]`. Сервер слушает только `127.0.0.1:8000`; Vite проксирует `/api`. Та же настройка есть у `npm run preview`.

`npm run api` устанавливает Python-зависимости из `uv.lock`, создаёт отдельный кластер в `.wuji-data/postgres`, применяет миграции и запускает API и отдельный процесс расчёта. PostgreSQL использует приватный Unix socket в `.wuji-data/run`, без TCP-listener. Системные службы и другие базы не меняются. Ctrl+C останавливает API и worker; если скрипт сам запустил кластер, он также останавливается. Данные остаются на диске.

Для отдельного управления процессами: `python3 scripts/dev-api.py --no-worker`, затем из каталога `backend` команда `uv run python -m app.worker`. Очередь сохранена в PostgreSQL; состояние читается через API.

Настройки через переменные окружения:

| Переменная | Значение по умолчанию |
| --- | --- |
| `WUJI_DATA_DIR` | `.wuji-data` в корне репозитория |
| `DATABASE_URL` | Локальный socket-кластер WUJI, база `wuji`, роль `wuji` |
| `OPENAI_API_KEY` | Не задан; текстовый разбор отключён |
| `WUJI_AI_MODEL` | `gpt-5.4-mini-2026-03-17` |
| `WUJI_AI_MAX_COST_MICRO_USD` | `50000` = 0,05 USD |

Внешний `DATABASE_URL` должен использовать драйвер `postgresql+psycopg://`. Если он задан, локальный кластер не создаётся, миграции выполняются в указанной базе. `.env` автоматически не загружается. Ключи и строки подключения во фронтенд не передаются.

## Проверки и контракт

```bash
npm test
npm run test:api
npm run api:types:check
npm run build
```

Backend-тесты создают временную базу `wuji_test_<uuid>` в отдельном локальном кластере, применяют настоящие миграции и удаляют только эту временную базу. Тесты отказываются работать с произвольным `DATABASE_URL`.

После изменения серверных схем:

```bash
npm run api:types
```

Это обновляет `backend/openapi.json` и `src/features/workspace/api/schema.d.ts`. Типы Employee, Shift, SourceVersion, TaskSpec и Scenario во фронтенде берутся из этого сгенерированного контракта.

Документация работающего API: `/docs` на адресе backend. Полный контракт импорта, маршруты и проверенные сценарии — в [DATA_STAGE.md](../docs/DATA_STAGE.md).
Расчёт, статусы поиска, очередь и закрепления — в [CALCULATION_STAGE.md](../docs/CALCULATION_STAGE.md).
Черновики из текста, контракт передачи данных, очередь, тарифы и автономная проверка — в [INTENT_STAGE.md](../docs/INTENT_STAGE.md).
Ручные версии, повторная проверка, локальное утверждение и файлы результата — в [APPROVAL_STAGE.md](../docs/APPROVAL_STAGE.md).

Для браузерной проверки без ключа: `npm run ai:preview` вместо обычного API. Используются отдельная временная база и явно обозначенный контрольный провайдер. Worker выполняет настоящие расчёты. Этот режим не подтверждает доступность или качество реальной модели.

## Хранение

- PostgreSQL: проекты, черновики импорта, исходники, версии условий, очередь Run, события, проверенные сценарии, метрики, Evidence и ссылки на текущие версии.
- `.wuji-data/objects`: оригинальные байты по SHA-256, с проверкой hash перед подтверждением и выдачей оригинала.
- Подтверждение импорта блокирует строку проекта и проверяет исходную версию. Конкурирующий старый предпросмотр получает `409`.
- SourceVersion и TaskSpec создаются добавлением строки. PostgreSQL-триггеры отклоняют их `UPDATE` и `DELETE`.
- Повтор подтверждения того же импорта возвращает ту же версию и не перемещает текущую версию назад.
- Новый исходник создаёт отдельные начальные условия. Задача предыдущего исходника остаётся доступна в его истории.
- Входы Run и терминальные результаты защищены PostgreSQL-триггером. Новый результат не перемещает текущие версии проекта.
- Черновики intent хранят текст, hash, точные входные версии, prompt/model, разрешённое предложение, usage, события и происхождение live/test. Подтверждение создаёт TaskSpec атомарно; входы и завершённые предложения защищены отдельным триггером.
- Ручные ревизии, их проверки, утверждения, ключи повторов и квитанции экспорта неизменяемы. Утверждение хранит полный снимок входов и результата, а экспорт — байты по SHA-256. История выдачи не утверждает публикацию.

Все проверки: `npm run check`. CI workflow добавлен в `.github/workflows/verify.yml`, но в GitHub ещё не запускался.

Это контур для локальной разработки. Аутентификация, многопользовательская изоляция рабочих областей, общий хостинг, лимиты хранилища и сборка для пилота относятся к последующим этапам. Этот сервер не подключён к Vercel-деплою лендинга.
