# WUJI — ручные версии, утверждение и экспорт результата

2 ноября 2026 года. API 0.5.0, миграция 0005. Реализован законченный локальный цикл этапа 5. Общий пилот с несколькими пользователями ещё не готов: аутентификация, изоляция рабочих областей и реальный обезличенный пример остаются отдельной работой.

## Работающий цикл

1. Открыть конкретный завершённый расчёт текущих SourceVersion и TaskSpec.
2. Выбрать вариант и просмотреть назначения, последствия и независимые проверки.
3. При необходимости открыть «Изменить назначения», выбрать смену и сотрудника, сохранить ручную версию.
4. Новая ручная версия получает статус «не проверено». Отдельно выполнить серверную проверку.
5. После пройденной проверки подтвердить просмотр назначений и условий, затем утвердить точную версию.
6. Подготовить CSV-набор или XLSX. Сервер сохранит неизменяемый файл и квитанцию с размером и SHA-256.
7. Скачать готовый файл. Браузер дополнительно сверит тип, размер и hash полученных байтов.

Расчёт, ручная правка, проверка, утверждение, подготовка файла и публикация имеют разные состояния. Никакие изменения во внешнюю рабочую систему не отправляются.

## Ручная версия

Правка создаёт immutable ScenarioRevision с собственными ID и номером R. Сохранены исходный Run, исходный вариант, родительская ручная версия, SourceVersion, TaskSpec, hash исходника и полный набор назначений.

Для каждой исходной смены требуется ровно один известный ID сотрудника. Нельзя добавить неизвестную смену, потерять исходную строку или создать пустое изменение. Обязательные правила при сохранении не ослабляются: их нарушение сохраняется как непроверенная правка, которую нельзя утвердить.

Проверка выполняется существующим независимым валидатором: версии/ID, покрытие, доступность и отсутствие, роли, закрепления, личные часы и пересечения. Результат, метрики и Evidence записываются отдельно и неизменно. Для новой версии валидатора возможна новая запись проверки; прежняя сохраняется.

Ручная версия не наследует доказательство оптимальности CP-SAT. Даже после 7/7 она обозначается как проверенная ручная версия без выполненной оптимизации. До проверки метрики помечены предварительными, а общая проверка не выдаётся за пройденную. В трёх областях показаны назначения и основания именно открытой версии.

Правка утверждённой версии создаёт следующий R. Прежнее утверждение и его файлы сохраняются; новая версия требует своей проверки и утверждения. Несохранённые назначения блокируют утверждение открытой версии.

## Что фиксирует утверждение

Неизменяемый снимок включает:

- полный нормализованный исходник с provenance и hash;
- точную версию условий, отсутствие, закрепления и приоритет;
- Run и версию движка;
- ID варианта или ручной версии, назначения и их candidateHash;
- независимую проверку, метрики, Evidence и статус поиска;
- время решения, local_user, подтверждение неизвестной оплаты и externallyApplied=false.

local_user означает оператора локального интерфейса. Это не аутентифицированная учётная запись и не электронная подпись.

Перед утверждением сервер блокирует проект, проверяет текущие версии и оригинальные байты по SHA-256, повторно вычисляет проверки/метрики/Evidence и сравнивает их с показанной сохранённой версией. Несовпадение приводит к конфликту. При fail или unknown утверждение запрещено. Если оплата неизвестна, требуется отдельная отметка; отсутствие суммы не превращается в ноль.

У проекта одно выбранное утверждение. Другое решение сохраняется новой записью и становится выбранным. Повтор с тем же ключом возвращает прежнее решение и не перемещает выбор назад. Одновременные подтверждения одинакового кандидата создают одно утверждение; отдельные request receipts сохраняют ключи повторов.

Новый исходник или новые условия делают прежнее утверждение историческим. Они не переписывают снимок. Ответ старого запроса не заменяет актуальное состояние интерфейса.

## Подготовка и скачивание

Файл строится только из утверждённого снимка. Текущие несохранённые поля не используются.

Первичная подготовка разрешена для выбранного утверждения текущих входных версий. По одному утверждению, формату и версии экспортёра существует один файл; повтор возвращает ту же квитанцию и те же байты.

Уже готовый файл остаётся доступен из истории, даже когда выбран другой вариант или появилась новая SourceVersion. Новый формат для устаревшего утверждения не готовится. Перед выдачей проверяются hash оригиналов и hash сохранённого артефакта; повреждение даёт явный 409, без молчаливой подмены.

Квитанция означает «файл подготовлен». Она не утверждает, что пользователь сохранил файл на диск, разослал его сотрудникам или применил расписание.

Файлы хранятся в существующем content-addressed FileStore; запись атомарна, байты доступны только для чтения. PostgreSQL запрещает UPDATE/DELETE ревизий, проверок, утверждений, ключей повторов и квитанций экспорта.

## Содержимое файлов

CSV-набор — ZIP:

| Файл | Содержание |
| --- | --- |
| schedule.csv | Итоговые назначения и исходные интервалы/роли |
| employees.csv | Сотрудники, роли, ставки в minor units и лимиты минут |
| availability.csv | Доступность, включая действие отсутствия |
| changes.csv | Смена, прежний и новый сотрудник, исходная строка |
| conditions.json | Точная TaskSpec |
| input-source.json | Полный входной снимок до изменения |
| approval.json | Версии, происхождение, решение и externallyApplied=false |
| validation.json | Проверки и версия валидатора |
| metrics.json | Часы, изменения, покрытие, суммы или null |
| evidence.json | Правила, арифметика и исходные ячейки |
| metadata.json | Команда, часовой пояс и валюта |
| manifest.json | SHA-256 логических файлов |

XLSX содержит Schedule, Employees, Availability, Metadata, Approval, Metrics, Validation, Changes, Conditions и Audit. В Audit полностью сохранены JSON-документы по нумерованным частям; длинные данные не обрезаются до предела ячейки. Заголовки продолжают чёрно-зелёное оформление WUJI. Текстовые ячейки не исполняются как формулы.

Деньги сохраняются в целых minor units, длительности — в минутах. Валюта указана явно. Неизвестные денежные величины остаются null в JSON и пустыми в XLSX. Метрики и журнал не обещают соответствие правилам, которые отсутствуют в текущем предметном контракте.

Дополнительные закрепления превращаются в pinned итоговых смен. Отсутствие переводится в unavailable на затронутых интервалах, включая пересечения. Эти производные значения позволяют прочитать результат новым исходником без потери условий; исходные факты до преобразования доступны в input-source.json.

При обратном импорте создаётся новый SourceVersion. Прежний статус утверждения и встроенные проверки не переносятся. Импортёр распознаёт объявленный формат WUJI с Audit/manifest, показывает предупреждение о новом исходнике, а изменённые таблицы — дополнительное предупреждение. Встроенный manifest является проверкой целостности, не подписью и не разрешением доверять расписанию. Новые данные проходят обычный импорт и последующие проверки.

Лимиты повторного импорта сохранены: до 5000 смен, 500 сотрудников, 50000 строк доступности и 5 МБ на входной файл. Разреженная доступность не заполняется миллионами неуказанных unknown. XLSX ограничен 5 МБ сжатых и 20 МБ раскрытых данных, CSV-набор — 40 МБ; превышение возвращает явную ошибку без потери строк.

## API

Префикс: /api/v1/projects/{projectId}.

| Действие | Маршрут |
| --- | --- |
| Варианты и до 50 последних ручных версий, плюс выбранная утверждённая версия | GET /runs/{runId}/review |
| Сохранить ручную версию | POST /runs/{runId}/revisions |
| Проверить ручную версию | POST /revisions/{revisionId}/validate |
| До 100 последних утверждений | GET /approvals |
| Конкретное утверждение и квитанции | GET /approvals/{approvalId} |
| Утвердить кандидата | POST /approvals |
| Подготовить формат | POST /approvals/{approvalId}/exports |
| Получить байты готового файла | GET /exports/{exportId}/download |

Ручная правка передаёт sourceVersionId, taskSpecId, baseScenarioId, parentRevisionId, assignments и requestKey. Утверждение — точные версии, runId, scenarioId, revisionId, candidateHash, acknowledged, acknowledgedUnknownCost и requestKey. Экспорт — format и candidateHash.

Все ссылки проверяют принадлежность проекту. Это предотвращает смешение объектов проектов в операции; аутентификацию и многопользовательскую защиту такая проверка не заменяет.

## Проверка и воспроизведение

Обычный локальный запуск: npm run api и npm run dev в разных терминалах. Для этого этапа ключ OpenAI не нужен. В сохранённом проекте выполнить расчёт, открыть правку назначений или утвердить готовый вариант, затем подготовить и скачать файл.

Общая команда:

```bash
npm run check
```

Проверено: 120 backend-тестов с настоящим PostgreSQL, 39 тестов TypeScript/HTTP-клиента, соответствие OpenAPI и production-сборка. Есть одно предупреждение стороннего TestClient о будущей замене HTTP-клиента.

Новые проверки охватывают неизвестные ID, отсутствие, роли, закрепления, лимиты, неизвестную доступность и стоимость; снятие статуса проверки; новые входные версии; повреждение оригинала/артефакта; конкурентные повторы; неизменяемость; новый экземпляр API; повторное чтение CSV/XLSX и изменённого XLSX без переноса утверждения. Клиент отвергает HTML вместо файла, неверный тип, размер и SHA.

В браузере на синтетическом проекте проверены R1 с нарушением часов, исправленная R2 с 7/7, подтверждение, скачивание обоих форматов и восстановление после перезагрузки. Исходник V3 и TaskSpec V9 сохранены. R2 содержит 2 перестановки, 112 часов, покрытие 14/14, оплату 31 040 RUB и разницу −640 RUB.

Снимки, образцы и результаты перезапуска: [approval-preview/](./approval-preview/).

## CI и граница пилота

Добавлен .github/workflows/verify.yml: Ubuntu 24.04, Node 22.22.3, Python 3.12, uv 0.11.11, PostgreSQL 16 и npm run check. Actions закреплены на проверенных commit SHA. Использованы официальные инструкции [checkout](https://github.com/actions/checkout), [setup-node](https://github.com/actions/setup-node), [setup-uv](https://github.com/astral-sh/setup-uv). Доступ к OpenAI не требуется.

YAML разобран локально, а команды проверены на текущем Mac. Workflow в GitHub не запускался: изменения не отправлялись в репозиторий. Проверка Linux runner остаётся до первого удалённого запуска.

Сохранена локальная граница: loopback API, приватный socket PostgreSQL, один оператор. Перед общим пилотом нужны аутентификация, рабочие области с владельцами и проверка доступа всех сущностей, лимиты хранения и настоящий обезличенный эпизод. Успешный живой ответ OpenAI и качество модели также ещё не подтверждены по ранее принятому решению работать без API. Во внешние системы расписание не записывается.
