# Сборка недели для отдела операторов

Дата проверки: 24 ноября 2026 года. Документ описывает сборщик расписания. Он открывается по отдельной ссылке `/fs_csr_schedule`; с лендинга на него входа нет. Демо с починкой готовой недели описано в [WORKSPACE_DEMO.md](./WORKSPACE_DEMO.md) и открывается по `/workspace`.

## Зачем

Отдел операторов составляет неделю вручную в таблице. Инструмент собирает её с нуля по правилам отдела, показывает, какое правило нарушено и где, и отдаёт результат в том же виде, в каком отдел ведёт таблицу. Им пользуются сами операторы, поэтому всё работает в браузере: сервера нет, данные никуда не отправляются.

## Что работает

- Две области: настройки слева (команда либо цели по дням и правила) и широкое расписание справа. Неделя и кнопка сборки вынесены в строку над ними. На узком экране области переключаются вкладками.
- Крупный шрифт и слова вместо сокращений: `Mon`, `Non-voice`, `Pacific time`. Обозначения отдела (`Mo`, `n/v+v`, `11/23`) остались только в выгрузке для их таблицы.
- Выбор недели: кнопка с датами открывает календарь, где каждая строка — неделя целиком. Отмечены открытая неделя, сегодняшний день по времени отдела и недели, у которых уже есть расписание.
- Гайд из пяти шагов при первом открытии; потом он открывается кнопкой «How it works» в шапке.
- Команда: ник, часовой пояс, норма смен в неделю, лимит коротких смен 2-8, оценки «сильно / обычно / слабо / никогда» по типу смены (голос, неголос) и по времени (ранние, дневные, поздние). Операторов можно добавлять и убирать.
- Цели по дням: желаемое число людей и сколько из них на неголосе. Каждая неделя хранится отдельно.
- Расписание: сетка оператор × день (`6-2.30`, `Non-voice`, `off`, `vacation`), время отдела или местное время каждого оператора, проверки, нагрузка за неделю, покрытие линий по получасам для выбранного дня.
- Ячейку можно закрепить: выходной, отпуск или конкретная смена. Закреплённое сразу попадает в неделю и сохраняется при каждой пересборке.
- Сборка solver-ом в отдельном потоке, с отменой. Проверки пересчитываются при любой правке.
- Сохранение в `localStorage`, перенос между людьми файлом, выгрузка в CSV и в буфер обмена для таблицы.
- Выгрузка недели в PDF для чата: та же тёмная таблица, одна страница. В файле нет названия проекта, логотипа и адреса сайта, в свойствах файла только нейтральный заголовок. PDF повторяет выбранные на экране часы: тихоокеанские или местные.

Страница открывается на неделе 23–29 ноября 2026 года из таблицы отдела: по ней видно, что проверки согласуются с расписанием, которое отдел составил сам.

## Правила в модели

Время отдела — `America/Los_Angeles`, работа с 6:00 до 20:00 каждый день.

| Смена | Часы | Оплачивается | Обед |
| --- | --- | --- | --- |
| `6-2.30` | 6:00–14:30 | 8 ч | да |
| `8-4.30` | 8:00–16:30 | 8 ч | да |
| `9.30-6` | 9:30–18:00 | 8 ч | да |
| `11.30-8` | 11:30–20:00 | 8 ч | да |
| `2-8` | 14:00–20:00 | 6 ч | нет |

Тип смены: `v` закрывает голосовую линию, `n/v+v` закрывает обе.

Жёсткие правила:

1. В любой момент рабочего дня на каждой линии есть хотя бы один оператор.
2. На каждой смене 8,5 ч есть получасовое окно для обеда: не в первый и не в последний час смены, по одному человеку за раз, и обе линии остаются закрытыми без ушедшего.
3. У оператора ровно его норма смен за неделю, за вычетом запрошенных выходных и отпуска, если дней не хватает.
4. Оценка «никогда» запрещает тип смены или время. Коротких смен не больше лимита оператора.
5. Запрошенные выходные, отпуска и закреплённые смены сохраняются.

Предпочтения (уступают правилам): сильные стороны, желаемое число людей по дням, одно время начала у оператора в течение недели, выходные подряд.

Часовые пояса на расчёт не влияют: они только показываются.

## Как считает solver

Модель — целочисленная линейная задача, решает её HiGHS, собранный в WebAssembly (пакет `highs`, MIT). Жёсткие правила сделаны «эластичными», поэтому неделя возвращается всегда. Поиск идёт в две фазы:

1. Минимум суммарного нарушения правил. Если он равен нулю, все правила выполнены. Если поиск завершён и минимум больше нуля, доказано, что неделя без нарушений невозможна, а показанная — ближайшая.
2. Лучшие предпочтения при том же уровне нарушений. Поиск останавливается, когда до лучшего возможного остаётся не больше 3 %, либо по времени.

Общий предел — 15 секунд. Результат проверяет `checkWeek` — отдельный код, который не знает о модели: обед он проверяет паросочетанием операторов и получасовых окон, а не формулами solver-а.

Обеды считаются по группам «смена + тип»: операторы одной смены и одного типа взаимозаменяемы, поэтому достаточно числа обедающих в каждом промежутке дня. Это сократило модель втрое по сравнению с переменной на каждого оператора.

## Данные и приватность

Репозиторий и сайт публичные. В коде только рабочие ники и обобщённые часовые пояса: фиксированное смещение (`Etc/GMT-5`) или регион с переводом часов (`CET`, `EET`). Фамилий, городов и внутренних номеров нет.

Оценки сильных и слабых сторон конкретных людей в код не зашиты: все начинают с «обычно» по типу смены. Время суток, в которое оператор работал в образцовой неделе, отмечено как сильная сторона. Реальные оценки отдел вводит сам; они остаются в браузере и в файле, который отдел передаёт друг другу.

В таблице поясов отдела у нескольких записей смещение на час отличается от базы часовых поясов на ноябрь 2026 года. В коде стоят значения базы; какие именно записи расходятся, передано владельцу отдельно, а не записано здесь.

## Допущения, которые стоит подтвердить у отдела

- Обед не берут в первый и последний час смены (`LUNCH_MARGIN`).
- «По очереди» понято как «один человек на обеде одновременно во всём отделе», а не отдельно по линиям.
- Оплачиваемые 15-минутные перерывы отдельно не моделируются: если есть окно для обеда, есть и для перерыва.
- У короткой смены `2-8` нет обязательного обеда.
- Неделя считается отдельно от соседних: отдых между воскресеньем и понедельником и справедливость выходных между неделями не учитываются.
- Желаемое число людей по дням (8 в будни, 4 в субботу, 5 в воскресенье) взято из одной образцовой недели.

## Как устроен PDF

Неделя рисуется на canvas теми же шрифтами, что и страница, в двойном разрешении. Пиксели сжимаются встроенным в браузер `CompressionStream` и кладутся в PDF как единственное изображение страницы; где `CompressionStream` нет, в тот же файл кладётся JPEG. Текст в таком PDF не выделяется: это картинка. Файл весит около 350 КБ и создаётся за доли секунды.

## Как проверить

```bash
npm run dev
```

Открыть `/fs_csr_schedule`.

1. При первом открытии показан гайд; после «Start» страница показывает неделю 23–29 ноября, семь проверок пройдены.
2. Нажать «Rebuild the week» в верхней строке: через несколько секунд статус «Every rule holds», источник `SOLVER`.
3. В области команды раскрыть оператора и поставить неголосу «Weak»: проверка сильных сторон становится предупреждением, ячейки подсвечены, появляется заметка об изменённых настройках. После пересборки у оператора только смены `v`.
4. Выбрать ячейку и закрепить выходной: проверки пересчитаны сразу, в сетке значок `▣`. После пересборки выходной на месте.
5. Переключить «Each operator’s local time»: в ячейках местное время, у оператора без пояса остаётся время отдела с пометкой `PT`.
6. Нажать на даты недели: открывается календарь. Выбрать другую неделю: она пустая, собирается с нуля.
7. «Download PDF»: сохраняется одностраничный файл с таблицей недели.
8. «Save to file», затем «Load from file» с этим файлом: команда и недели на месте. Повреждённый файл отклоняется с причиной, данные не меняются.

```bash
npm test
npm run build
```
