# Первая итерация WUJI: рабочее пространство

Дата проверки: 1 ноября 2026 года. Документ описывает первую демонстрационную итерацию. Реализованное позднее сохранение и импорт описаны в [DATA_STAGE.md](./DATA_STAGE.md).

Реализован отдельный маршрут `/workspace`. Вход — `WORKSPACE ↗` в desktop-навигации и мобильном меню лендинга. Страница загружается отдельным модулем, дополнительные стили ограничены классом `.workspace`.

## Что работает

- Три области с независимой прокруткой и начальной пропорцией 35/30/35.
- Разделители: перетаскивание мышью, стрелки клавиатуры, Home для восстановления пропорций.
- Исходная таблица и карточки десяти сотрудников.
- Пять подготовленных ситуаций и переключение вариантов результата.
- Связь назначения, изменения и основания по устойчивому ID смены.
- Просмотр источника, условия, доступности и денежной разницы для выбранной смены.
- Подсчёт перестановок, затронутых людей, назначенных часов, смен и оплаты.
- Проверки конечного набора данных примера: ссылки и версии, покрытие, доступность, роли, закрепления, лимиты часов, пересечения.
- Переключение именованных областей на узком экране, клавиатурный переход к задаче, состояния фокуса.
- Явное предупреждение при редактировании свободного запроса: варианты продолжают относиться к исходному примеру.

Заранее подготовленные варианты не являются результатом поиска solver. ИИ, пользовательский импорт, серверное сохранение, утверждение и экспорт результата относятся к следующим этапам. В интерфейсе их статус показан явно. Перезагрузка открывает исходный пример заново.

## Входной контракт примера

Одна команда, неделя 2–8 ноября 2026 года, `Europe/Moscow`, `RUB`. Все имена и значения синтетические. Деньги хранятся в копейках, лимиты времени — в минутах. Каждая смена длится восемь часов и требует одного человека указанной роли.

В [examples/](./examples/) есть отдельный набор для каждой ситуации:

| Файл | Поля |
| --- | --- |
| `team_week_02-08_nov.csv` | `shift_id, starts_at, ends_at, role, employee_id, pinned` |
| `employees.csv` | `employee_id, name, roles, rate_per_hour_minor, max_weekly_minutes, currency` |
| `availability.csv` | `employee_id, shift_id, availability` |
| `conditions.json` | ID примера, версия источника, часовой пояс, валюта, задача, отсутствие и правила |

Время содержит явное UTC-смещение. Роли в CSV разделены `|`. Пустая ставка означает неизвестное значение. `availability` принимает `available`, `unavailable`, `unknown`; в примере явно перечислены все 140 пар сотрудник–смена. Условие об отсутствии накладывается поверх исходной доступности. Неизвестность не считается подтверждением доступности.

Номер строки в UI включает строку заголовка CSV: `s05` находится в строке 6, `s08` — в строке 9. Бандлы создаются из тех же исходных данных, что показаны в интерфейсе, командой `npm run demo:fixtures`. Тесты сверяют существенные строки и версии.

Типы контракта находятся в `src/features/workspace/model/types.ts`, примеры — в `data/examples.ts`. Это ограниченный контракт демонстрации. Он требует проверки на обезличенных реальных таблицах до реализации импорта для пилота.

## Контрольные результаты

Исходная оплата: `(300 + 280 + 260 + 300 + 300 + 280 + 280 + 250 + 300 + 300 + 270 + 260 + 280 + 240) × 8 = 31 200 ₽`, 14 смен, 112 часов.

| Ситуация | Ожидаемое поведение |
| --- | --- |
| Анна отсутствует в среду | София заменяет Анну в `s05`: 1 перестановка, 2 затронутых человека, `+160 ₽`, итог `31 360 ₽` |
| Вариант с меньшими затратами | Денис берёт `s05`, Олег берёт `s08`: 2 перестановки, 3 человека, `−480 ₽`, итог `30 720 ₽`. Денис сохраняет лимит 8 ч |
| Ставка Софии неизвестна | В первом варианте сумма и денежная разница неизвестны; часы и число перестановок остаются известными |
| Доступность Софии неизвестна | Первый вариант требует уточнения, проверка доступности не пройдена; второй вариант остаётся допустимым в рамках примера |
| Отсутствующая Анна закреплена в `s05` | Показано прямое противоречие двух обязательных условий. Готовый допустимый вариант не предлагается |
| Неделя без изменений | 0 перестановок, 0 затронутых людей, `0 ₽` разницы, исходные назначения сохранены |

Денежная разница по второй перестановке: `(240 − 250) × 8 = −80 ₽`. Первая перестановка экономичного варианта: `(250 − 300) × 8 = −400 ₽`. Их сумма — `−480 ₽`.

## Как воспроизвести

```bash
npm run dev
```

Открыть `/workspace` на адресе, напечатанном Vite. Для тестов и генератора примеров нужен Node.js 22.6+ с поддержкой удаления TypeScript-типов; проверено на 22.22.3.

```bash
npm test
npm run build
```

Браузерный маршрут проверки:

1. Войти через `WORKSPACE ↗` с главной страницы.
2. Выбрать «Меньше затрат»: увидеть две перестановки, три затронутых человека и `−480 ₽`.
3. Нажать вторую перестановку: слева выбрана `s08`, в центре — строка 9, Денис → Олег и расчёт `−80 ₽`.
4. Последовательно открыть случаи неизвестной ставки, неизвестной доступности, конфликта и отсутствия изменений.
5. Изменить свободный запрос: увидеть предупреждение, затем восстановить текст примера.
6. Проверить оба разделителя мышью и клавиатурой; Home возвращает 35/30/35.
7. На ширине 390 открыть задачу, перейти к вариантам, нажать изменение и вернуться к исходной строке.
8. Перезагрузить `/workspace`, проверить прямое открытие, затем вернуться на лендинг.

## Визуальная проверка

Эталоны исходного сайта находятся в [design-baseline/](./design-baseline/README.md). Скриншоты рабочего пространства — в [workspace-preview/](./workspace-preview/README.md).

Проверены desktop 1440×900 и 1280×800, узкий экран 390×844, отсутствие горизонтальной прокрутки страницы, фокус и переходы между областями. Текущие палитра, шрифты, изображения, геометрия и CRT-оформление сохранены. В лендинг добавлена точка входа; логотип выделен в общий компонент с прежней разметкой. При уходе с лендинга удаляется его callback GSAP, чтобы плавная прокрутка не оставляла лишние обработчики после возврата.

Итоговые проверки: `npm test` — 15 тестов пройдены; `npm run build` — успешно. Собранная версия дополнительно открыта через `vite preview` по прямому `/workspace`: три области, метрики, связанные выделения, неизвестная сумма, конфликт и мобильный вход работают. В свежей вкладке production-версии предупреждений и ошибок консоли не обнаружено.

Изменения продукта не публиковались во внешний сервис. Это локальная реализация первой итерации.
